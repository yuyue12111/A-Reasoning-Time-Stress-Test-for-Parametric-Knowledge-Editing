# 矿场产物使用协议（一页版，随交付包拷入 why-aaai27）

fable 起草，2026-07-23。交付包 = style_notes.md + transfer_checklist.md + 本协议，仅此三件。

## 角色定位（最重要的一条）

这些是**修订层透镜，不是起草原料**。论文的内容、数字、论证全部继续来自
WRITING_PLAN + results.json；透镜只在已有稿子之后过筛。检查问题是问题不是指令——
"语料多数如此"从不构成"你必须如此"，**有意偏离 + 知道为什么偏离**是完全合法的答案
（v5 的高数字密度即范例：偏离语料常态，但对本 track 是有意且正确的）。

所有量化观察基于 **accepted-only 语料，携带幸存者偏差**，且当前为
`RELIABILITY_NOT_RUN / PROVISIONAL_UNCERTIFIED` 描述性透镜——不是"顶会规则"，
不能推断"这样写导致接收"，不得写进论文当依据。

## 摘要工作流（至 7/25 内部冻结）

1. 基线 = 已提交的 v5，逐字不动放左边。
2. 用 Abstract 检查组逐句过 v5，每条记三态：符合 / 有意偏离（附一句理由）/ 打磨机会。
3. 只针对"打磨机会"起草候选版：数字、CI、hedge 语法逐字沿用 v5 台账；候选版每句
   须映射回 v5 对应句（"非实质性修改"的可审计证明）。
4. 过自家审计链：数字对账 checker → 禁语扫描 → 非实质性检验（AAAI-27 规则：改到
   qualitatively different = 未审拒稿）→ 敌意冷读。
5. 明确胜出才替换，否则保 v5。7/25 与全文一起冻结；OpenReview 表单与 PDF 同步更新
   （表单编辑权至 7/28 UTC-12 = 北京 7/29 19:59）。

## 六条禁令

1. 不从 style_notes 反推或想象语料论文的原句（文档设计上不含任何原句）。
2. 论文中不引用、不提及矿场项目及其任何产物。
3. 量化观察是描述性透镜，不是规范，不得作为论文中任何陈述的依据。
4. 检查问题与冻结 claim hierarchy 或禁语清单冲突时，论文自身规则无条件优先。
5. 透镜不得用于加强任何 claim（包括"语料都这么自信所以我们也可以"）。
6. 数字只有一个来源：results.json。透镜里的数字都是关于语料的，与论文无关。

勘误单向推送——收到勘误时只需更新透镜读数，不影响已完成的三态判断逻辑。
